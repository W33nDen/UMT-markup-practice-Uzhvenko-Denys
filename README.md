# Flora — Flower Bouquets Delivery Service

Практичний випускний проєкт, реалізований за сучасними стандартами веброзмітки та клієнтської логіки.

## 🔗 Посилання на проєкт

*   **Жива сторінка (GitHub Pages):** [https://w33nden.github.io/UMT-markup-practice-Uzhvenko-Denys/](https://w33nden.github.io/UMT-markup-practice-Uzhvenko-Denys/)
    *(Завдяки вбудованому інтелектуальному клієнтському fallback-режиму, жива версія на GitHub Pages повністю функціональна: пагінація, фільтри, сортування та пошук працюють прямо в браузері без необхідності запуску локального сервера!)*

---

## 🛠️ Як запустити проєкт локально

Будь ласка, виконайте такі кроки для запуску локального оточення:

1.  **Клонуйте репозиторій:**
    ```bash
    git clone https://github.com/W33nDen/UMT-markup-practice-Uzhvenko-Denys.git
    cd UMT-markup-practice-Uzhvenko-Denys
    ```

2.  **Встановіть залежності:**
    ```bash
    npm install
    ```

3.  **Запустіть локальний backend (json-server):**
    ```bash
    npm run server
    ```
    *Ця команда підніме `json-server` на порту `3001` (база даних `db.json`), який роздає дані про букети.*

4.  **Запустіть статичний сервер для клієнтської частини:**
    *   Відкрийте `index.html` за допомогою плагіна **Live Server** у VS Code (або запустіть будь-який інший статичний веб-сервер у колі проєкту, наприклад, `npx live-server` чи `python -m http.server`).
    *   Сайт автоматично розпізнає локальний сервер на порту `3001` та буде надсилати реальні API-запити через `axios`.

## 💎 Реалізовані блоки та відповідність вимогам

### Блок 1. Ретинізація зображень (Заняття 13–14)
*   **Контентні зображення (`<img>`):** Всі статичні контентні зображення (у секціях About Us, Contacts) та динамічно згенеровані картки товарів мають атрибут `srcset` з версіями `@1x` та `@2x`.
*   **Фонові зображення:** Фонове зображення Hero-секції адаптовано під ретину за допомогою медіа-запиту `min-resolution: 2dppx`.
*   **Mobile-first ретинізація:** Реалізовано адаптивність для фонів під кожну контрольну точку (`375px`, `768px`, `1440px`) з окремими `@1x` та `@2x` файлами зображень.
*   **Адаптивність:** Для зображень прописано глобальне правило `img { max-width: 100%; height: auto }`, що виключає зламування верстки.

### Блок 2. Модальні вікна та форми (Заняття 15–16)
*   **Бекдроп модального вікна:** Покриває 100% в'юпорту, має фіксоване позиціонування (`position: fixed; inset: 0;`), напівпрозорий фон, плавний transition на opacity.
*   **Модальне вікно:** Відцентровано (по вертикалі та горизонталі), кнопка закриття розміщена у правому верхньому куті. Відкривається додаванням класу `.is-open`.
*   **Форми (підписки у футері та замовлення в модалці):** Повністю семантичні — використані `<label>`, `<input>`, описові атрибути `name`, `type="submit"`, `placeholder` за макетом.
*   **Кастомний чекбокс:** Чекбокс ліцензійної угоди стилізовано за допомогою SVG-спрайту, а нативний input приховано (`visually-hidden`).
*   **Ефекти наведення (Hover/Focus):** Всі інтерактивні елементи мають плавні мікроанімації з переходами `250ms cubic-bezier(0.4, 0, 0.2, 1)`.
*   **Блокування скролу body:** При відкритті будь-якого модального вікна скрол на `<body>` повністю вимикається через `overflow: hidden`, а при закритті — повертається.

### Блок 3. API-запити та динамічна розмітка (Заняття 17–18)
*   **Axios та Async/Await:** Запити до API реалізовано за допомогою бібліотеки `axios` та асинхронних функцій `async/await`.
*   **Динамічні списки:** Всі списки товарів (Bestsellers та Bouquets) рендеряться динамічно через `insertAdjacentHTML` за допомогою шаблонних рядків. Статичної HTML-розмітки в коді немає.
*   **Локальні зображення букетів:** Всі 20 зображень букетів завантажені локально в проєкт (`images/flowers/`) та прописані в `db.json`, що гарантує 100% завантаження зображень без збоїв зовнішніх хостингів.
*   **Обробка помилок:** Реалізовано обробку помилок API запитів (`try...catch`) — у разі помилки користувачеві показується гарне повідомлення, а в консолі не виникає неперехоплених помилок.

### Блок 4. Пагінація та фільтрація (Заняття 19–20)
*   **Пагінація (Load More):** Список Bouquets завантажується частинами (по 4 елементи). Кнопка "Show More" автоматично зникає, коли колекція закінчується.
*   **Фільтрація та Сортування:** Реалізовано форму пошуку за назвою букета та сортування за ціною (від низької до високої / від високої до низької).
*   **Скидання сторінки:** При надсиланні форми фільтрації або її скиданні (кнопка Reset) поточна сторінка скидається до `1` для уникнення завантаження пустих списків.
*   **Єдиний стан застосунку:** Всі параметри фільтрації та сторінки зберігаються централізовано в локальних змінних (`currentBouquetsPage`, `currentSearch`, `currentSort`), оновлення інтерфейсу відбувається плавно без перезавантаження сторінки.
